# 과제 틀

과제를 처음 정할 때 못 박은 것만 둔다. 출처는 운영 폴더의 `개발 내용.txt`, `모임 개요.txt`, 옛 요구사항서 v3.0.1 의 1.2절과 2.3절, 기술 스택 결정(2026-09-27)이다.

| ID | 항목 | 내용 |
|---|---|---|
| ST-01 | 목표 | 모임 관리를 대충 할 수 있게 하는 앱을 만든다. 일정 조율에 전화를 돌리던 일, 공지 문구를 매번 다시 쓰던 일, 발표 녹화와 자료를 찾아 올리던 일을 앱 하나에서 처리한다 |
| ST-02 | 1차 필수 기능 | 디스코드 공지, 모임 일정 관리(각자 되는 시간을 넣으면 공통 빈 시간을 찾는다), 파일 업로드, 자료 공유 공간, 관리자 페이지, 회원가입과 로그인. 여섯 가지 모두 1차에 들어간다 |
| ST-03 | 기한 | 1차는 2026-09-21 부터 2026-11-20 까지다. 2차 기간은 따로 정한다 |
| ST-04 | 플랫폼 | 스마트폰 앱(Android, iOS), PC 앱(Windows, macOS), 웹에서 같은 기능을 쓴다. 반응형 웹이 아니라 네이티브 앱이다 |
| ST-05 | 기술 스택 | 앱은 Flutter 코드 하나로 만든다. 인증, DB, 파일 저장은 Supabase 셀프호스팅이 맡는다. 후보 시간 계산과 디스코드 발송은 Go 보조 서버가 맡는다 |
| ST-06 | 로그인 | 이메일과 비밀번호로 가입하고 로그인한다. 아이디는 받지 않는다 |
| ST-07 | 서버 | 미니PC 한 대에 Docker Compose 로 띄운다. 특정 클라우드나 호스팅에 묶이지 않는다 |
| ST-08 | 쓰는 사람 | 모임 회원만 쓰는 비공개 앱이다. 외부에 공개하는 서비스가 아니다 |
| ST-09 | 보안 바닥 | 키, 토큰, 비밀번호는 저장소에 넣지 않는다. 권한 검사는 서버에서 한다. 화면에서 숨기는 것만으로 권한을 나누지 않는다 |
| ST-10 | 1차 범위 밖 | 주제 요청, 개인 프로필, 구글 OAuth, 발표자에게 보내는 메모장, 커뮤니티 게시판은 2차다. 라이브 스트리밍과 녹화, 영상 자막 추출은 서버 사양을 확인한 뒤 2차에서 검토한다 |

ST-02 의 기능 하나하나가 어떻게 동작하는지는 여기 적지 않는다. `가변/기능/` 에 적는다.
