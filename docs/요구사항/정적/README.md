# 정적 요구사항

과제가 처음 정한 틀이다. 개발 중에 바뀌지 않는다는 전제로 다른 모든 문서와 코드가 이 위에 선다.

## 에이전트는 고치지 않는다

Claude, Codex 등 AI 에이전트는 이 폴더를 읽기만 한다. 세 겹으로 막는다.

| 막는 곳 | 하는 일 |
|---|---|
| `.claude/settings.json` | Claude Code 의 파일 수정 도구가 이 폴더를 고치지 못하게 거부한다 |
| `.claude/hooks/static_req_guard.py` | Claude Code 가 셸 명령으로 이 폴더에 쓰거나, 아래 라벨을 다는 것을 막는다 |
| `.github/workflows/static-req.yml` | 이 폴더나 위 두 파일을 바꾼 PR 은 `정적 요구사항 변경` 라벨이 없으면 실패한다. Codex 처럼 Claude 설정을 읽지 않는 에이전트도 여기서 걸린다 |

에이전트가 일하다가 정적 요구사항과 맞지 않는 일을 만나면 멈추고 사람에게 묻는다. 우회해서 고치지 않는다.

## 사람이 바꿀 때

1. 이슈를 연다. 제목은 `[정적 요구사항] <바꿀 것>` 이고, 왜 바꿔야 하는지와 영향을 받는 모듈을 적는다.
2. 팀이 합의하면 사람이 직접 고쳐 PR 을 연다. 모듈은 `골격` 으로 고른다.
3. 사람이 PR 에 `정적 요구사항 변경` 라벨을 단다. 라벨이 붙으면 `static-req` 검사가 다시 돌고 통과한다.
4. 바뀐 내용을 `.claude/memory/skeleton/결정.md` 에 결정으로 남긴다. 가변 요구사항 중 부딪히는 것이 있으면 같은 PR 이나 바로 다음 PR 에서 고친다.

라벨이 아직 없으면 저장소 관리자가 한 번 만든다.
`gh label create "정적 요구사항 변경" --color B60205 --description "정적 요구사항을 사람이 바꾼 PR"`
