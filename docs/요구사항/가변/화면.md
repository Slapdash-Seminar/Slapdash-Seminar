# 화면 설계

- 담당: 따로 정하지 않았다. 화면을 바꾼 사람이 이 파일의 표도 고친다
- 정본: Figma 파일 [대충하는발표회 화면](https://www.figma.com/design/zFasxjz9m8ewZ2idlqjqOW/Document)

화면 설계는 가변이다. 개발하면서, 써 보면서, 회의에서 언제든 바꾼다. 정적 요구사항(`../정적/과제 틀.md`)은 모두 화면보다 우선한다. 예를 들어 ST-02 필수 기능, ST-04 플랫폼, ST-06 이메일 로그인, ST-09 보안 바닥과 맞지 않는 화면은 고친다. 정적을 바꿔야 할 것 같으면 화면을 맞추지 말고 멈춰서 사람에게 묻는다(`README.md`).

같은 파일의 `실험1`~`실험5`, `Page 1` 페이지는 시안을 고르던 기록이다. 개발 기준으로 쓰지 않는다. 파일을 열려면 Figma 권한이 있어야 한다. 없으면 저장소 관리자에게 요청한다.

## 섹션과 모듈

두 페이지 모두 기능별 섹션으로 나눈다. 섹션 이름은 두 페이지가 같다.

| 섹션 | 모바일 | PC | 주로 맡는 모듈 |
|---|---|---|---|
| A 로그인 · 가입 | 7 | 7 | `member` |
| A 모임 고르기 · 새 모임 추가 | 7 | 7 | `team` |
| B 홈 · 모임 정보 | 7 | 7 | `skeleton`(홈), `team`(모임 정보) |
| C 일정 | 16 | 16 | `schedule` |
| D 소식 · 공지 | 15 | 15 | `notice` |
| E 자료실 | 7 | 8 | `file` |
| F 내 정보 · 설정 | 8 | 8 | `member`(내 정보, 설정), `team`(모임 설정) |

## 화면 이름

- 모바일은 `<섹션 글자>-<번호> <화면> · <상태>` 로 쓴다. 예: `C-05 후보 시간 투표 · 회원`.
- PC 는 모바일 이름에서 번호를 빼고 앞에 `PC` 를 붙인다. 예: `PC 후보 시간 투표 · 회원`.
- 2026-11-21 기준으로 모바일 화면마다 같은 이름의 PC 화면이 있다. 두 페이지를 꼭 하나씩 맞춰야 하는지는 정하지 않았다.

두 페이지 모두 프로토타입 흐름이 있다. Figma 오른쪽 위 재생 단추로 연다.

| 번호 | 흐름 |
|---|---|
| 1 | 로그인과 가입 |
| 2 | 홈 (팀장). PC 는 9 PC 앱이 같은 자리에서 시작한다 |
| 3 | 일정 정하기 (팀장) |
| 4 | 소식 (회원) |
| 5 | 공지 쓰기 (팀장) |
| 6 | 자료실 (팀장) |
| 7 | 내 정보와 모임 설정 |
| 8 | 새 모임 추가 |
| 9 | PC 앱 (PC 페이지에만 있다) |
| 10 | 일정 요청 보내기 (팀장) |

불러오는 중, 불러오지 못함, 빈 상태처럼 상태만 보여 주는 화면은 다른 화면에서 눌러 가는 길이 없을 수 있다. 섹션에서 직접 연다.

## 화면을 바꿀 때

1. Figma 에서 바꾼다. 같은 화면이 다른 페이지에도 있으면 그쪽도 볼지 확인한다.
2. 동작이 바뀌지 않고 배치만 바뀌었으면 요구사항 파일은 그대로 둔다. 기능 요구사항에는 배치를 쓰지 않는다(`README.md` 한 줄의 꼴).
3. 동작이 바뀌었으면 먼저 그 모듈 담당과 맞춘다. 기능 요구사항 줄과 상태, 근거는 `README.md` 의 고치는 법과 에이전트 규칙대로 고치고, 결정은 `.claude/memory/<모듈>/결정.md` 에 남긴다.
4. 섹션이나 화면 수, 흐름이 바뀌었으면 이 파일의 표를 고친다.
5. 저장소 밖 작업이라 PR 이 없으면 `.claude/rules/work-sharing/공유 못 할 때.md` 대로 알린다.

## 코드와 화면이 다를 때

코드를 짜다가 화면과 다르게 해야 할 까닭이 생기면 그 모듈 담당에게 알린다. 화면과 `기능/<모듈>.md` 의 동작이 서로 다르면 어느 쪽에 맞출지 모듈 담당에게 묻는다.

## 지난 자료

옛 화면설계서와 클릭 데모(운영 폴더의 `[1차] 화면설계서`, `[1차] 화면 데모`)는 Figma 로 옮기기 전 기록이다. 저장소에 두지 않고 개발 기준으로 쓰지 않는다.
