# 작업 공유 절차

함께 일하는 사람(과 그 사람의 Claude)이 헤매지 않게, 하는 일을 늘 보이는 곳에 둔다.
보이는 곳은 두 군데다. **지금 하는 일은 Draft PR**, **끝난 일과 결정은 `.claude/memory/<모듈>/`**.
Claude 는 스킬 `work-share` 로 이 절차를 밟는다.

## 시작할 때

1. `git pull` 로 main 을 받는다.
2. 이어 받을 것을 본다.
   - `gh pr list --state open` 으로 같은 모듈에 열린 PR 이 있는지 본다. 있으면 그 사람과 먼저 말한다.
   - `.claude/memory/<모듈>/진행.md` 의 맨 위 몇 줄과 `결정.md` 를 읽는다.
   - `.claude/memory/_공유 대기/` 에 그 모듈 파일이 있으면 읽는다.
3. 브랜치를 따고(`repo-rules/모듈과 브랜치.md`), `memory/<모듈>/진행.md` 맨 위에 "시작" 줄을 쓴다.
4. 커밋해서 push 하고 Draft PR 을 연다. 제목은 `<모듈>: <요약>`. 본문은 한 줄이면 된다("작업 중, 무엇을").
   이제 팀원이 `gh pr list` 로 이 일을 본다.

## 하는 동안

- 결정이 생기면 그 자리에서 `memory/<모듈>/결정.md` 에 쓴다. 다른 모듈에 영향이 있으면 그 모듈 `진행.md` 에도 한 줄 쓴다.
- 작업을 쉬거나 끝낼 때마다(세션을 닫기 전, 사용량 한도가 가까울 때, 대화 압축 전) 커밋하고 push 한다.
  push 가 공유다. 로컬에만 있는 일은 남에게 없는 일이다.
- 남이 알아야 할 막힘이나 질문은 Draft PR 댓글로 남긴다.

## 끝낼 때

1. `진행.md` 맨 위에 "끝" 줄을 쓴다. 남은 일이 있으면 그 줄에 적는다.
2. 시험·검수를 마치고 PR 본문을 채워 Draft 를 푼다(`repo-rules/PR.md`).
3. 병합되면 memory 도 main 에 들어가 다음 사람이 읽는다.

## 공유할 수 없을 때

push 를 못 하거나, 저장소 밖에서 일했거나, 세션이 갑자기 끊기는 때가 있다. `공유 못 할 때.md` 를 따른다.
