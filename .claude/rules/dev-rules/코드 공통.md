# 코드 공통

앱, 서버, DB 모두에 적용한다. 언어별 규칙은 `Flutter.md`, `Go.md`, `Supabase.md` 에 있다. 여럿이, 여러 AI 가 짜도 한 사람이 짠 것처럼 보이게 하려는 규칙이다.

## 서식은 도구에 맡긴다

- 들여쓰기, 줄 끝, 인코딩은 루트 `.editorconfig` 와 `.gitattributes` 가 정한다. UTF-8, 줄 끝 LF, 파일 끝 빈 줄 하나다.
- 커밋 전에 포매터를 돌린다. Dart 는 `dart format`, Go 는 `gofmt`, SQL 은 손으로 맞춘다. 포매터 결과와 다투지 않는다.
- 서식만 바꾸는 커밋과 기능을 바꾸는 커밋을 나눈다(`커밋.md`).

## 이름

| 대상 | 쓰는 말 | 예 |
|---|---|---|
| 변수, 함수, 타입, 파일, 폴더, DB 이름 | 영어 | `voteScore`, `schedule_request` |
| 주석, 커밋 메시지, 문서 | 한국어 | `// 점수가 같으면 날짜가 빠른 쪽` |
| 화면에 보이는 글자 | 한국어 | `'일정 확정'` |

- 모듈 폴더 이름은 브랜치 머리와 같다(`schedule`, `notice` 등).
- 같은 것은 어디서나 같은 영어 이름으로 부른다. 처음 쓰는 도메인 이름은 `docs/요구사항/가변/용어.md` 에 한국어 용어와 함께 적는다. 예: 팀 `team`, 일정 요청 `schedule_request`, 가능 시간 `availability`, 후보 시간 `candidate_slot`, 순위 투표 `ranked_vote`, 공지 `notice`, 자료 `material`.
- 줄임말은 널리 쓰는 것만 쓴다(`id`, `url`, `db`). 새로 줄여 만들지 않는다.

## 주석

- 무엇을 하는지가 아니라 왜 그렇게 했는지를 쓴다. 코드로 읽히는 것은 쓰지 않는다.
- 요구사항을 구현한 곳에는 ID 를 남긴다. 예: `// FR-SCH-07: 점수가 같으면 날짜가 빠른 쪽`
- 할 일은 `TODO(@GitHub계정): 내용 #이슈번호` 로 쓴다. 이슈 없는 TODO 는 PR 에서 지적받는다.
- 주석으로 막아 둔 옛 코드를 남기지 않는다. 이력은 git 에 있다.

## 오류와 로그

- 오류를 삼키지 않는다. 잡았으면 사용자에게 보이거나, 로그에 남기거나, 위로 넘긴다.
- 사용자에게는 무엇을 하면 되는지 한국어로 보인다. 내부 오류 문구를 그대로 보이지 않는다.
- 로그에 비밀번호, 토큰, 이메일 전체를 남기지 않는다(`.claude/rules/repo-rules/비밀값.md`).

## 의존성과 설정

- 패키지를 새로 들일 때는 PR 본문 `변경 내용` 에 이름과 까닭을 적는다. 같은 일을 하는 패키지가 이미 있으면 그것을 쓴다.
- 주소, 포트, 키 같은 설정값은 코드에 박지 않는다. 환경 변수나 설정 파일에서 읽고, `.env.example` 에 이름만 둔다.

## 크기

- 함수 하나는 한 화면(50줄 안팎)을 넘기지 않게 나눈다. 파일 하나는 400줄을 넘기면 나눌 곳을 찾는다.
- 한 PR 에서 고친 줄이 500줄을 넘으면 나눌 수 있는지 먼저 본다. 생성된 파일(잠금 파일, 코드 생성 결과)은 세지 않는다.
